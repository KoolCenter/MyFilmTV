# MyFilmTV v0.7 — remediation update

## Changed
- Removed custom playback User-Agent, synthetic Referer, Accept-Language, and blanket cross-protocol redirect override. Default Media3 behavior is used.
- Per-source `playbackHeaders` is OPTIONAL and restricted to `User-Agent`, `Referer`, and `Origin`; only use when a source explicitly documents the header requirements. Existing sources.json remains compatible.
- Save `sourceId` / `vodId` for new records. Fetch `ac=detail&ids=<vodId>` when the user opens a title and use its current playback lines when available.
- Preserve separate records across providers, rather than deduplicating by film title/year and silently combining different editions.
- Database cursor and paged display are bounded at 50 cards per increment rather than mounting the entire cached library on screen. This is a **bounded GridLayout**, not yet RecyclerView virtualization.
- Background sync iterates all known type IDs/page cursors with a small request interval, rather than limiting each category to the first 2 pages. It only operates while the app foreground lifecycle allows it.
- Search includes paged local-cache matches; full remote search pagination is **not implemented**.
- History saves source/vod identity for newly played titles, plus selected line, URL and seek position.
- APK signing is configured for a stable secret-backed key; workflow intentionally fails if repository secrets are absent, rather than quietly producing a differently signed APK.

## Set signing secrets (required before GitHub Actions will build)
Generate a keystore on a trusted local machine and keep a backup outside GitHub. Set repository Actions secrets:
`MYFILM_KEYSTORE_B64` (Base64 contents of JKS), `MYFILM_STORE_PASSWORD`, `MYFILM_KEY_ALIAS`, `MYFILM_KEY_PASSWORD`.
PowerShell Base64: `[Convert]::ToBase64String([IO.File]::ReadAllBytes('C:\path\myfilm-release.jks'))`.
Example key generation: `keytool -genkeypair -v -keystore myfilm-release.jks -alias myfilmtv -keyalg RSA -keysize 3072 -validity 10000`.
A new signing certificate will NOT overwrite existing installs with a different signing cert. The first transition may require uninstall/reinstall and lose app data; subsequent builds with the same key can upgrade.

## Verification status
Source packages produced and structure checked. **No Gradle build / device runtime validation is available in this environment.**
HTTP 403 is not proved resolved: servers can still reject unauthenticated playback requests and indirect/webpage streams are not supported by default Media3.

## Remaining limitations
- Paged GridLayout still rebuilds at most the selected local slice; for very large datasets, RecyclerView is the better long-term implementation.
- Filter/sort acts on the cached prefix loaded in this view, not on remote entire catalog; remote results can be incomplete.
- Title detail URL handling supports MacCMS `ac=detail&ids`, not arbitrary proprietary provider parsers.
